02八个 Key Points

1｜瓶颈变了

从晶体管密度转向工程师生产力。AI 的首要价值不是“省人”，而是突破人类可处理的工程复杂度上限。

2｜终局不是 Copilot

Agent 会理解目标、制定计划、调用工具、读取结果并反复修正。核心链路是 Action → Result → Reasoning。

3｜Solver 才是判据

LLM 负责推理与编排；simulation、formal、STA、lint、CDC 等可信工程引擎提供 ground truth。

4｜单位从 Tool 变为 Workflow

入口从“运行 Jasper”升级为“证明 DPC 触发后的 containment 正确”。EDA 从 Tool-Centric 转为 Intent-Centric。

5｜稀缺能力是 Design Intent

工程师的价值从 How 上移到 What + Why：定义 requirement、invariant、coverage model 与 oracle。

6｜Agent 必须长时间运行

它需要状态、记忆、恢复、等待、执行和迭代能力。普通 Chatbot 不等于 Engineering Agent。

7｜GPU 反过来加速 EDA

GPU → 加速 EDA → 更快设计 GPU，AI、HPC 与 EDA 将形成新的性能飞轮。

8｜边界扩展到 System

优化对象从 transistor、chip 扩展到 package、rack、cooling、data center 与 workload。

03最关键的提问方式变化

旧问题

AI 怎么保证不 hallucinate？

试图让概率模型自身成为真理源。

新问题

如何强制每个关键结论通过工程 oracle？

用多源证据和可执行引擎，让错误能够被暴露、定位和纠正。

04对验证 Agent 的直接启示

不要只做一次性的 AI Testplan Generator，而应构建可持续闭环的 Verification Reasoning System。

输入：Spec / RTL / Interface / Design Intent
建模：Requirement Graph → Feature Model → Verification Model
执行：Stimulus / Checker / Coverage → Simulation / Formal / Lint
证据：Evidence DB 保存需求、测试、日志、覆盖率与证明结果的追踪关系
闭环：Reasoning Agent 做 gap finding、debug、修正与再运行
结构层核心作用
Requirement Graph保存需求、来源、依赖、冲突与追踪关系
Feature Model用维度和组合描述功能空间
Verification Model把需求映射到 stimulus、checker、coverage
Evidence DB保存每项结论的仿真、formal、日志与覆盖证据
Oracle用可执行引擎判断对错，而非依赖语言模型自证

05最值得带走的五个认知

  1. AI 扩大工程设计空间，不只是替人写代码。
  2. EDA 主入口从 Tool 转向 Intent：人说明要证明什么。
  3. LLM 不是真理源：Simulator、Formal、Compiler 和 checker 才是 oracle。
  4. 验证工程师向 verification architect 迁移：核心是 requirement、invariant、coverage 与证据。
  5. Agent 的核心不是生成，而是闭环。
Generation is cheap. Verification is the moat.

06个人能力建设

设计意图建模

把自然语言需求转化为 requirement、约束与 invariant。

验证空间划分

用正交维度、状态机、因果链和组合覆盖描述完备性。

证据链设计

让结论可追溯到 Spec、RTL、接口、测试和工具结果。

闭环架构

让 Agent 运行工具、读取反馈、定位缺口并继续迭代。

最终要问的问题

怎样把验证工程变成一个可由 Agent 自主规划、执行、获得证据、发现缺口并持续闭环的系统？
